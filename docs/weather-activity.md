# 雨落成诗活动协议与实现

## 活动范围

本次活动为 `2026-08-26` 至 `2026-09-08` 的“雨落成诗”。本页结论来自小游戏 `1.13.3.11_20260826`、TSDK `v3.9.0.1787640848` 的实际登录、使用道具、触发雷雨、形成闪电变异、收获和推进研究链路。

活动协议组为 `2026070300`，子活动如下：

| 子活动 | 协议用途 |
| --- | --- |
| `2026070301` | 金豆豆兑换天气采集瓶与活动说明 |
| `2026070302` | 雷雨中的闪电变异配置 |
| `2026070303` | 天气采集瓶奖励配置 |
| `2026070304` | 气象研究线路与节点状态 |
| `2026070305` | 获取雷电徽章的气象任务 |

## 实际玩法结论

- 雷雨中成长中的作物基础闪电变异概率为 `18%`，1 品和 2 品作物除外。
- 闪电变异配置编号为 `12`，成熟果实售价为普通售价的 `4` 倍。
- 雷雨召唤瓶为物品 `5002`。实机使用后 `WeatherService.GetWeatherStatus` 返回的起止时间相差 `7200` 秒。`ItemInfo.json` 的旧描述仍写 20 分钟，因此运行时和 Web 页面以服务端起止时间为准。
- 天气采集瓶为物品 `5001`，只能在仍处于雷雨状态的好友农场使用；配置返回成功采集必得雷雨召唤瓶 `×1`。
- 雷电徽章为活动货币 `1027`。使用天气采集瓶、使用雷雨召唤瓶和收获闪电变异作物分别对应任务奖励。
- 实机已完成召唤、闪电变异收获、任务奖励和研究节点 `1000` 推进。研究操作消耗 20 枚雷电徽章并获得天气采集瓶 `×1`。

## 协议结构

活动读取使用 `ActivityService.GetGroup`。`ActivityData` 中与本活动有关的字段为：

| 字段 | 定义 |
| --- | --- |
| `102` | 兑换商店目录 |
| `105` | 天气采集瓶与产出配置 |
| `117` | 气象任务列表 |
| `118` | 气象研究线路、节点状态、消耗和奖励 |

好友摘要 `GameFriend.field_20` 为 `WeatherStatus`。自己或当前访问农场的天气通过 `WeatherService.GetWeatherStatus` 读取；天气变化通知为 `WeatherChangeNotify`。

天气瓶统一调用 `ItemService.Use`：

- 天气采集瓶的 `target.host_gid` 为已进入且仍有雷雨的好友农场；
- 雷雨召唤瓶的 `target.host_gid` 为自己的农场；
- 两种请求都显式使用 `use_config_id=0`。

推进气象研究调用 `ActivityService.Operate`：

- `activity_id=2026070304`；
- `operate_type=40`；
- 节点选择器为 `field_140.node_id`。

## Web 与自动化行为

活动中心的“气象观测台”展示服务端活动时间、自己农场的雷雨倒计时、有效好友雷雨、道具余额、气象任务和研究线路，并提供以下实际操作：

- 每日兑换天气采集瓶；
- 在有效好友农场采集天气；
- 在自己的农场召唤雷雨；
- 推进当前可用且徽章足够的研究节点。

每次写操作前都会重新核对背包、天气或研究节点状态。好友采集会先进入好友农场，再读取现场天气；无论成功或失败都会离开好友农场，避免访问状态残留。

邮箱奖励不再因为当天已经检查过就永久短路。运行账号会每 5 分钟重新发现两个邮箱类型中的新附件；批量领取等待正式响应，网关返回错误时再降级为单封领取。

## 当前限制

天气采集瓶必须有合法雷雨好友目标。没有有效好友时页面只保留道具并说明原因，不会尝试伪造目标。活动任务协议当前只下发任务定义和每日上限，没有单独的活动进度字段；页面因此展示真实任务定义，不虚构完成百分比。
